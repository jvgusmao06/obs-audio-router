# Design Doc: Arquitetura v1.0 — Dispositivo Virtual Único, Pass-through Silencioso e Instalador

**Data**: 2026-11-04  
**Status**: Proposto / Em Avaliação  
**Autor**: Antigravity & User  

---

## 1. Contexto e Motivação (Intent & Why)

Na versão v0.4.x, o **OBS Audio Router** avançou na separação visual e no controle de faders duplos (Fone e Live) diretamente no OBS através de captura por processo do Windows (`wasapi_process_output_capture`).

Contudo, identificamos a limitação fundamental do subsistema de áudio do Windows (WASAPI Loopback):
1. Quando uma aplicação (ex: Spotify, Discord, Jogo) renderiza diretamente na saída física do fone de ouvido, o Windows aplica o volume da sessão (`ISimpleAudioVolume`) **antes** de entregar os dados para o loopback da captura.
2. Como resultado, se o usuário diminui o volume no fone (ou muta nos ouvidos), o Windows entrega áudio atenuado ou zerado para a live/gravação no OBS.
3. Se o OBS tentar monitorar o processo para os fones enquanto o app ainda toca no fone nativamente, gera duplicação e eco.

A solução definitiva adotada pelo mercado (SteelSeries Sonar, Elgato Wave Link) é o uso de dispositivos virtuais de áudio. Porém, essas ferramentas pecam pelo excesso de complexidade:
- Instalam 5 ou mais dispositivos virtuais poluindo o seletor de áudio do Windows.
- Exigem aplicativos pesados em Electron (consumindo 300MB a 600MB de RAM, com dezenas de threads e telemetria constante).
- Se tornam um incômodo quando o streamer não está fazendo live.

### O Objetivo da v1.0
Entregar uma experiência **ultraleve**, **robusta** e **invisível**:
1. **Apenas 1 dispositivo de áudio virtual no Windows** (ex: *OBS Audio Router*).
2. **Separação de canais exclusiva dentro do OBS** (*Game, Chat, Media, System*) via o plugin.
3. **Comportamento nativo quando o OBS estiver fechado**: o som do computador passa direto para o fone físico (áudio cru do Windows), sem nenhuma intervenção manual.
4. **Instalador profissional executável (.exe)** via Inno Setup que instala tudo com 1 clique.

## 2. Metas, Não-Metas e Anti-Metas

### Metas (Goals)
- **Dispositivo Virtual Único**: Adicionar apenas 1 endpoint de reprodução no Windows, mantendo o sistema limpo.
- **Isolamento de Volume Total (0% a 100%)**:
  - Usuário pode deixar a música em 0% no fone e 100% na live sem que um interfira no outro.
  - Usuário pode escutar o chat alto no fone e baixo na transmissão.
- **Pass-through Silencioso em C++ (Modo OBS Fechado)**:
  - Um executável auxiliar em C++ (`obs-audio-router-bridge.exe`) pesando menos de 500 KB e consumindo < 3 MB de RAM.
  - Quando o OBS está **fechado**: o bridge repassa o áudio do dispositivo virtual diretamente para o fone físico de forma 1:1 (áudio cru, baixa latência).
  - Quando o OBS está **aberto**: o plugin do OBS sinaliza um mutex/evento IPC global; o bridge pausa imediatamente o repasse; o plugin do OBS assume o controle de mixagem e monitoramento independente para o fone físico.
  - Quando o OBS **fecha**: o bridge retoma instantaneamente o repasse 1:1 para o fone.
- **Instalador Inno Setup (.exe)**:
  - Detecta o diretório do OBS Studio automaticamente.
  - Instala a DLL do plugin (`obs-audio-router.dll`), traduções e o executável do bridge.
  - Instala e configura o dispositivo virtual com assinatura WHQL válida.
  - Registra desinstalador limpo no Painel de Controle do Windows.
- **Compilação Automatizada no GitHub Actions**:
  - Workflow do GitHub gera o arquivo `OBS-Audio-Router-Setup-v1.0.0.exe` nos releases.

### Não-Metas (Non-Goals)
- Criar interfaces pesadas em Electron/Web.
- Criar 4 ou 5 dispositivos virtuais no Windows (o Windows verá apenas 1).
- Modificar drivers não assinados que exijam modo de teste do Windows (`testsigning on`).

### Anti-Metas (Anti-Goals)
- Não exigir configuração manual de cabos pelo usuário no Windows.
- Não deixar o usuário sem som quando o OBS for fechado.
- Não gerar eco ou feedback loop.

## 4. Detalhamento dos Componentes

### 4.1. Dispositivo Virtual de Áudio (Endpoint Único)
- Utiliza um driver virtual assinado digitalmente com compatibilidade WHQL (ex: núcleo do VB-Audio Cable ou driver WDM assinado).
- Nome exibido no Windows: **OBS Audio Router (Dispositivo de Reprodução)**.
- O instalador configura esse dispositivo como a saída padrão do Windows, caso o usuário selecione a opção recomendada.

### 4.2. Bridge de Segundo Plano (`obs-audio-router-bridge.exe`)
- **Tecnologia**: C++ nativo (Win32 + WASAPI Audio Engine puro).
- **Consumo**: < 3 MB de RAM, 0% CPU em repouso.
- **Mecanismo de Sincronização IPC**:
  - Cria um `CreateEvent(NULL, TRUE, FALSE, L"Global\\OBSAudioRouterActiveEvent")`.
  - Enquanto o evento estiver **não-sinalizado** (OBS fechado):
    - O bridge lê as amostras do dispositivo virtual e escreve diretamente no endpoint físico padrão (headphones) usando buffer WASAPI de baixa latência (10ms).
  - Quando o evento estiver **sinalizado** (OBS aberto):
    - O bridge entra em repouso (`WaitForSingleObject`) e para a renderização, liberando o dispositivo físico para o plugin do OBS sem gerar eco.
  - Ao fechar ou crashar o OBS, o Windows fecha o handle do evento automaticamente, fazendo o bridge despertar e restabelecer o som do Windows instantaneamente.

### 4.3. Plugin do OBS (`obs-audio-router.dll`)
- Ao iniciar: abre/sinaliza o evento `Global\OBSAudioRouterActiveEvent`.
- Captura os processos atribuídos a cada canal (**Game, Chat, Media, System**).
- Como as aplicações estão tocando a 100% de volume no dispositivo virtual:
  - O loopback do OBS recebe o sinal 100% limpo e sem atenuação.
  - O fader **Live** define o ganho da faixa da transmissão.
  - O fader **Fone** renderiza o áudio para o dispositivo físico de fones (via WASAPI render direto ou barramento de monitor do OBS) no nível exato escolhido pelo usuário.
  - **Fader Fone em 0%** = silêncio absoluto no ouvido do usuário, mas 100% na live.
- Ao encerrar: fecha o evento IPC, devolvendo o controle para o bridge.

### 4.4. Instalador Inno Setup (`installer/setup.iss`)
- Script Inno Setup compilado via `iscc` no GitHub Actions:
  - Detecta se o OBS Studio está instalado (via registro e caminhos padrão).
  - Instala a DLL em `obs-studio/obs-plugins/64bit/obs-audio-router.dll`.
  - Instala os arquivos de localização em `obs-studio/data/obs-plugins/obs-audio-router/locale/`.
  - Instala o executável `obs-audio-router-bridge.exe` em `%LOCALAPPDATA%\OBSAudioRouter\` e cria atalho na inicialização do Windows (`Run`).
  - Executa a instalação silenciosa do dispositivo virtual.
  - Inclui desinstalador limpo (`unins000.exe`).

## 5. Princípios Ponytail Aplicados

1. **Rung 1 (YAGNI)**: Apenas 1 dispositivo virtual no Windows, não 5. Nenhum painel externo em Electron ou interface web desnecessária.
2. **Rung 2 & 3 (Reuse & Native)**: O bridge de áudio utiliza WASAPI nativo do Windows em menos de 150 linhas de código C++, sem bibliotecas pesadas de terceiros.
3. **Rung 5 (Existing Packages)**: Inno Setup para empacotamento padrão do Windows, amplamente suportado e sem fricção.
4. **Boundary de Segurança**: Uso de driver com assinatura WHQL para garantir que o Windows 11 não rejeite com Erro 52 e não comprometa jogos com anti-cheat.
