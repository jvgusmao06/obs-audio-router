# v1.0 Installer and Virtual Audio Architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete v1.0 architecture featuring a single virtual audio device, an ultra-lightweight C++ audio passthrough bridge (< 3MB RAM) for seamless audio when OBS is closed, independent volume isolation (0-100%) in the OBS plugin, and an Inno Setup installer with clean uninstallation.

**Architecture:** A single virtual audio device is installed on Windows. When OBS is closed, `obs-audio-router-bridge.exe` runs silently in the background passing raw 1:1 audio to the user's physical headphones. When OBS opens, the OBS plugin signals an IPC event (`Global\OBSAudioRouterActiveEvent`), pausing the bridge so the plugin can perform per-process channel mixing with 100% independent monitor vs. stream volume control. An Inno Setup installer packages the plugin DLL, bridge, driver setup, and registers a clean uninstaller in Windows.

**Tech Stack:** C++20, Win32 API (IPC Events), WASAPI (Audio Client / Render / Capture), Inno Setup 6, GitHub Actions CI.

**Spec:** [`docs/superpowers/specs/2026-11-04-v1.0-installer-and-virtual-audio-architecture.md`](file:///c:/Users/Jvgso/Projetos/apps/obs-audio-router-plugin/docs/superpowers/specs/2026-11-04-v1.0-installer-and-virtual-audio-architecture.md)

## Global Constraints

- Windows 10 (64-bit build 20348+) and Windows 11 only.
- Single virtual audio endpoint in Windows playback devices list (no multi-device clutter).
- Background bridge memory footprint under 3 MB RAM, 0% CPU when idle or paused.
- Zero audio echo: bridge must release or pause output immediately when OBS audio router is active.
- Clean uninstallation: must terminate processes, restore defaults, remove files, and unregister cleanly.

## Review Focus

1. **OBS crash or abrupt termination:** The bridge must detect that the OBS process/event handle closed and automatically resume passthrough within 1 second so the user is never left without sound.
2. **OBS launch while bridge is already streaming:** The bridge must immediately pause its render loop upon event signal to avoid audible glitch or echo.
3. **Bridge started when OBS is already open:** The bridge must immediately enter sleep/pause state rather than starting passthrough.
4. **Virtual device not present:** The plugin and bridge must fail gracefully without crashing or throwing unhandled exceptions, falling back to native mode.
5. **Uninstaller executed while bridge or OBS is running:** The uninstaller must cleanly request or force termination of `obs-audio-router-bridge.exe` before deleting files.

### Task 4: Inno Setup Script & Clean Uninstaller Automation

**Files:**
- Create: `installer/setup.iss`
- Create: `installer/scripts/detect-obs.pas`
- Create: `scripts/build-installer.ps1`
- Test: Validate syntax with Inno Setup compiler (`iscc`) or CI verification.

**Interfaces:**
- Produces:
  - `OBS-Audio-Router-Setup-v1.0.0.exe` installer.
  - Windows registry keys: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\OBSAudioRouterBridge`.
  - Windows Uninstall entry with automatic process termination and cleanup.

- [ ] **Step 1: Create Inno Setup script `installer/setup.iss`**

Script specifies:
- AppName: `OBS Audio Router`
- AppVersion: `1.0.0`
- DefaultDirName: Auto-detected OBS installation folder (`HKLM\SOFTWARE\OBS Studio` fallback to `C:\Program Files\obs-studio`).
- Files installed:
  - `obs-audio-router.dll` -> `{app}\obs-plugins\64bit\`
  - `locale\*.ini` -> `{app}\data\obs-plugins\obs-audio-router\locale\`
  - `obs-audio-router-bridge.exe` -> `{localappdata}\OBSAudioRouter\`
- Startup entry: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` for the bridge.
- `[UninstallRun]` section: terminates `obs-audio-router-bridge.exe` via `taskkill /F /IM obs-audio-router-bridge.exe`.
- `[UninstallDelete]` section: cleans up all created directories.

- [ ] **Step 2: Create PowerShell helper script `scripts/build-installer.ps1`**

Script accepts plugin build artifact directory, compiles the bridge, and invokes `iscc installer/setup.iss /DAppVersion=1.0.0 /DSourceDir=...`.
